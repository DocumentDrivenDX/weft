schema/instance E2E and the local Ashlar/Spark4/Delta4 publication E2E on
2026-10-16. Truss retains its actual accepted schema/binding identities. Ashlar

## Original authored-Key page programs

`compile_engine_page_json` accepts a closed `weft.engine-page/0.1` request with
an original compiler request and exact `pageSize` in1..999. It retains the full
native first-page artifact, visible outputs, hidden Key metadata and source.
`check_engine_page_json` recompiles the complete original before binding declared
scalar parameter values and an explicit lexical continuation. Context, schema,
SQL, original page bound and program drift refuse; Python/native input sizes and
portable UTF-16 handling are bounded before parsing. No token grants permission.

Truss uses its original runtime page compiler. Ashlar has separate explicit
`ashlar-spark4-pages` and `ashlar-dbsql-20261016-pages` compiler selections with
backend versions `0.1.0-local-spark4-pages-candidate` and
`0.1.0-managed-20261016-pages-candidate`, backend interface0.2.2 and compile0.2.2.
Their native physical engine profiles remain separately pinned. Historical
compile0.2.0 profiles are unchanged and cannot be relabeled as page programs.
These candidates require the original `ashlar.candidate.keyIntegrity` handler,
held native pin/publication scope and fresh complete closing resolution; compiler
success alone qualifies none of those host obligations.

The selected SDK carrier subset remains exact non-temporal string, boolean,
integer and decimal scalars. Typed Date/timestamp selection remains held even
when the underlying owner compiler supports its separately qualified profile.
