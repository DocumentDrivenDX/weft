# Weft v0.4.35

This candidate release adds a conditional result-refinement checker to the
standard Python wheel and an explicit Truss query ABI backend.

The existing original `CurrentQueryPreparation` exposes five named checker
methods for PostgreSQL rows, contributor bags and exact integer SUM, and
Databricks contributor bags and SUM. The checker validates actual lowering and
compares complete captured inputs with public values and complete contributors.
CONTRACT-010 specifies its closed frames, five digest anchors, exact types,
SQL tie/limit semantics and pre-limit size limits. A match remains conditional:
`authority=false`, `securityReady=false`, `nativeAdmission=required`.

Ordinary Truss backend `0.4.38` selects binding/target `0.5` with exact query ABI
`truss-postgresql-logical-query/1.0`. It supports directed owned and independent
relationship reads while preserving original binding bytes and all native
installation/runtime/model checks. Earlier backend selections retain their
closed pins and reject the new binding. Mutation admission is unchanged.

Local evidence includes 338 core, 105 PostgreSQL library and 15 Databricks library
tests, four query ABI compiler groups, 67 fresh PostgreSQL checker controls and
229 offline controls over 22 retained managed Databricks queries. Release CI
must also pass all five platform wheel jobs, including 30 exact-wheel refinement
controls per platform. Retained managed results are not a fresh cloud execution.

This release grants no native query permission and activates no protected
consumer cohort. B-008 remains open under all 132 original shared/native cases;
authenticated source/caller/current authority, complete native custody and guarded
release require their own qualified host enforcement and evidence.
