# Weft v0.4.33

Standard wheels now include the actual frozen CurrentQueryPreparation Python API
and conditional PostgreSQL current-value consumers. Version0.4.32's standard
feature selection omitted these APIs; existing published assets stay unchanged.
The release enables both truss-postgresql-pg18 and current-postgresql-scalar-candidate.
Every platform gate installs its exact wheel and exercises original-parent custody,
profile1/native-input1/consumerABI2 masked projection/raw predicate, ABI3 contributor
COUNT, explicit profile2/native-input2/ABI4 original integer SUM and no downgrade.
The retained proof records exact source, wheel, native module and shim digests.

These are experimental compiler/source-context APIs, not native permissions or
protected-backend registration. SQL artifacts retain authority:false,
securityReady:false and nativeAdmission:required. Hosts must enforce actual
installed sources, authenticated caller/Subject/current authority, complete route/
action admission, scalar/runtime correspondence, statement/result custody and
guarded release. The separately tested Truss first guarded query does not close
its confirmed alternate-read activation gap; no broad security claim follows.
B-008 and its original132 shared/native obligations remain open.

The original Truss native65/66/67 compatibility and mutation behavior are retained;
unknown release/binding mismatches still refuse. Current compiler consumers use
explicit independent ABI2/3/4 contracts. Package or static backend versions cannot
automatically select a newer consumer or grant authority. No database driver or
connection is introduced into the compiler, and no native key encoder is added.

The final Python extension retains debug line tables without changing release
optimization. This avoids the pinned-toolchain Mach-O debug-stripping alignment
failure observed on macOS27; exact installed-wheel imports remain mandatory.
Upstream diagnosis: https://github.com/rust-lang/rust/issues/157750 .
