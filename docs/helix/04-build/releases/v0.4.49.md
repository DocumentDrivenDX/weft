# Weft 0.4.49 selected-assets release preparation

This candidate contains the managed Unity Catalog current-core Weft targets and
the local Spark 4.2 / Delta 4.4.1 targets. The source/version change is prepared
but has not been committed, tagged, built through hosted Actions, natively
qualified on managed UC, or published. No release approval is implied.

The exact `v0.4.49` tag is excluded from the legacy four-platform build and
publisher. The selected Linux workflow builds only x86_64 manylinux2014 from an
explicit source SHA (which must also be the workflow dispatch commit) and stores
the wheel plus successful workflow run ID/name, source, RECORD, and native-module
hashes as an artifact. The Mac ARM64 helper requires a clean attached branch at
that same commit and builds into a temporary packaging-check environment. Promotion consumes
those existing wheel bytes and the qualification report staged on the draft tag;
it verifies both wheels and report lineage before publishing and does not rebuild
either platform.

The required qualification report is
`managed-current-uc-qualification-v0.4.49.json`, accompanied by hashed
Backend03 grouped/HAVING, Backend02 first-page, and Backend02 continuation case
assets, a route/case parity asset, and the exact prior local evidence packet.
The evidence assets are named `managed-current-uc-case-backend03-grouped-having-v0.4.49.json`,
`managed-current-uc-case-backend03-negative-having-v0.4.49.json`,
`managed-current-uc-case-backend02-page1-v0.4.49.json`,
`managed-current-uc-case-backend02-continuation-v0.4.49.json`,
`managed-current-uc-program-parity-v0.4.49.json`, and
`current-native-query-and-sdk-pages-20261021.json` plus its three referenced compressed native reports:
`positive_grouped_graph_query.json.gz`, `negative_having_query.json.gz`, and `sdk_pages_2_plus_1.json.gz`.
Each native case must bind the source commit and selected Linux wheel/native
module, observed serverless runtime/principal, one unchanged manifest and four
data-role vector with the separate six-role inventory, the request/artifact/
SQL/ordered-parameter hashes, and expected and actual rows. The page case pair
must bind the 2+1 continuation. The publisher verifies these asset bytes and
refuses a status-only proof. The UC host admission and execution harness remains
a separate implementation/qualification gate; pure compiler binding alone is
not native managed execution.

The local native evidence from 0.4.48 is reusable only after the selected Mac
wheel performs effect-free recompilation of the retained local requests. The
release record must include the exact prior evidence packet reference and
successful route-specific equality comparison of the emitted target SQL and
ordered parameters against the compressed native reports; no whole local matrix
or Spark rerun is required for a package-version-only rebuild. This does not replace the required
managed UC execution on the exact 0.4.49 Linux wheel.

Source SHA, wheel digests, native RECORD digests, UC qualification proof, and
promotion run remain open until the source is frozen and the bounded qualification
is complete.
