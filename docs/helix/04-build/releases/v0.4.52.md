# Weft 0.4.52 selected-assets release candidate

This candidate pins source `32ec02f0c3fd24a97b7726500dc5992c6475908d` and the
selected Linux x86_64 manylinux2014 and macOS ARM64 wheels. It is prepared for
review only. No tag, workflow run, GitHub release, upload, or publication was
created for this candidate.

The two wheel files are bound by their retained build and packaging reports:

| Platform | Wheel SHA-256 | Native module SHA-256 | Scope |
|---|---|---|---|
| Linux x86_64, manylinux2014 | `9145b7f683dc84325cfe3ab7c4b885685db05be814a4d554a4b739ae43d5cbdc` | `a326a607898e4cbcf9f4801785059d096e8bdb0557f46818951c70db0d7a7956` | Run `39981671006`; exact archive, RECORD, metadata, ABI tag and notices checked |
| macOS ARM64 | `598509e981e3238961d33d430c711b481e430adc945e692a1784ab758f7b6d46` | `f4be63caaacedeaa3d8af1b1f0587c561a2ff1ae0a279f4f8f7dcf836f6bb24f` | Local release build and packaging receipts; compiler-only evidence below |

The macOS ARM64 selected wheel passed four managed-page compiler tests, two
managed current-read compiler controls and two selected public 0.4.51 Source-F
compiler cases. The exact functional receipt is retained under
[`release052-selected-assets-20261023`](../evidence/release052-selected-assets-20261023/runtime-32ec02f/mac-functional-receipt.json)
and is pinned by SHA-256
`16b987ebb2e0ad5e419676e5a63cd827ca3eb94716fd75d3afff31374c10e441`. The
Source-F cases preserve selected opaque payload output and refusal behavior.
UMF inputs are pinned to core `0.10.0` SHA-256
`49633924b45a3c8499d4fcc1a24c30d5a8fcb34d974ab019bbda987cb47da0f9` and
access `0.1.0.dev6` SHA-256
`8f6e86ed94983d0156c2d6e9e1bf83fae186fe1d4a288a3846722e64aa365cf0`.
The Linux/macOS asset pair passed the offline exact-asset verifier against the
live GitHub Actions run record; the [verification receipt](../evidence/release052-selected-assets-20261023/selected-assets-verification.json)
is retained with this evidence packet.

The candidate has an explicit selected-assets promotion workflow. The generic
release workflow excludes `v0.4.52` from its platform matrix and publisher. The
separate publisher requires a manually selected Linux run, the exact source SHA,
and these staged macOS draft assets: the ARM64 wheel, build receipt, packaging
report, `mac-functional-receipt-0.4.52.json`, `ashlar-page-tests-0.4.52.log`,
`ashlar-current-read-tests-0.4.52.log`, `source-f-results-0.4.52.json`,
`source-f-cases-0.4.52.json`, and `source-f-entity-reports-0.4.52.json`. The
publisher validates both wheels, source custody, RECORDs, native
modules and the compiler-only receipt. It reconciles all release assets by exact
bytes: identical existing names are skipped, mismatches are refused, and only
missing assets are uploaded. It verifies the final remote asset set and bytes
while the release is still a draft, then promotes it separately. It does not
rebuild the selected wheels. The workflow has not been run; the draft tag/release
and staging of the macOS assets remain future release operations.

The release tag must point to the reviewed metadata/workflow candidate commit,
which is a descendant of source `32ec02f`; it cannot point directly at `32ec02f`
because that source commit still contains the generic release matrix behavior.
The publisher separately pins `sourceCommit` to `32ec02f`, requires it to be an
ancestor of the tag commit, and rejects changes to compiler/build/contract inputs
between those commits. The tag commit SHA is recorded as `releaseMetadataCommit`.

The retained Linux workflow report is packaging-only. The current compiler-only
receipt is macOS-specific; no Linux compiler-only execution against the Linux
wheel and these UMF pins is claimed here. No native SQL backend, PostgreSQL,
Databricks, Unity Catalog or production behavior is qualified by this release
candidate. Support claims remain limited to the exact wheel platforms, ABI and
compiler evidence stated above.
