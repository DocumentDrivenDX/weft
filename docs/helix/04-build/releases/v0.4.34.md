# Weft v0.4.34

This release adds Truss native68 compatibility and a conditional Databricks SQL
consumer to the standard Python wheels. It is intended for backend implementers
integrating the experimental current-query APIs. Release assets are distributed
through GitHub Releases; exact source, wheel, extension and shim digests accompany
the five platform builds.

## Changes

Truss backend **0.4.37** accepts the exact `truss-catalog-runtime/0.68-candidate`
storage realization with manifest digest
`3588cf030cb46c7d12368557e351bd767c10b4dd2e1644f7f100cec54602a2fc`.
Backend 0.4.36 retains its native66/67 behavior and rejects native68. Backend
0.4.37 rejects older realizations. Ordinary queries and mutation selection retain
the existing supported subset and original-model checks. Unnamed records do not
acquire SQL names from their identifiers.

Standard wheels additionally enable `current-databricks-scalar-candidate`.
The two explicit Python entrypoints lower a retained current-query preparation
into Databricks SQL with named parameters, result codecs, complete contributor
bags and per-cell source metadata. The first supports the declared scalar,
join, grouping, COUNT and DISTINCT subset; the second explicitly admits original
signed-64-bit integer SUM. Inputs support required String and signed-64-bit
Integer fields within the declared subset. Databricks SUM uses exact
DECIMAL(38,0) accumulation or an error; it does not promise unbounded arithmetic.

The Databricks consumer retains separate versioned bindings and validates exact
source/designation correspondence. PostgreSQL consumers reject Databricks
bindings. Unknown profiles, mixed versions and unsupported operations refuse.
Versioned Delta relations, quoted identifiers, qualified native functions and
bound parameters preserve the declared physical access and value semantics.

## Required actions and migration

Backend operators must select backend 0.4.37 explicitly when installing the exact
native68 realization. Keep backend 0.4.36 for its existing realizations. Retain the
previous matching runtime and compiler wheels to roll back as a pair; do not
rewrite existing bindings or substitute a manifest digest.

A protected-query host must qualify and register the exact new extension digest.
A package upgrade does not migrate a protected consumer registration or grant
permission to use a newer result ABI. Existing compiler bindings remain closed.
Application callers have no automatic migration step.

## Validation and known limits

Native68 qualification includes actual public acceptance/create/query and
selection/update with unchanged named products-model bytes, ten exact-wheel
controls, and the complete 105-test PostgreSQL library suite. The original
unnamed Core07/Core08 fixtures still refuse SQL name resolution. The native68
realization is an owner-supplied draft, so installing this compiler does not
make that runtime a published release.

The Databricks SQL corpus exercised 22 emitted queries and three negative
controls on the managed warehouse, then removed its isolated test schema.
Those tests establish SQL/value/contributor behavior with synthetic admission
premises. Genuine Ashlar source authority, Unity Catalog policy custody and a
second authenticated caller remain required for security qualification.

All current-query compiler artifacts retain `authority:false`,
`securityReady:false` and `nativeAdmission:required`. Hosts must enforce actual
source installation, authenticated caller/Subject/current authority, complete
route/action admission, native value correspondence, statement/result custody
and closing validation before releasing results. B-008 and its original 132
shared/native acceptance obligations remain open.
