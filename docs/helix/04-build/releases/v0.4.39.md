# Weft v0.4.39

Adds canonical Truss date projection and equality through explicit compile/IR/backend protocol0.2.7, Truss backend0.4.41 and logical-query ABI1.1. Dates retain Gregorian YYYY-MM-DD tokens, years0001–9999. Literals and typed date parameters validate calendar dates; field joins compare with C-collated text equality. Absence and explicit null retain their separate projection states and do not match equality.

Consumers select the new protocol/backend and matching ABI explicitly. Older selections retain their existing behavior. Date ordering, ranges, key components and implicit date/string conversions are not added. The date domain is the explicit Truss subset; UMF core's declaration of the date family does not by itself establish every temporal refinement.

The release workflow requires all five exact platform wheels and their seven date compiler checks, alongside every retained standard wheel check. Release pins describe backend0.4.41/ABI1.1 separately from legacy backend0.4.40/native70; this does not claim a new fixed native runtime or protected security admission.

A paired Truss candidate passed public writes, commit/reopen and date queries on PostgreSQL18.6. Truss main adoption requires these published matching wheels. The Truss0.0.38 release and its unchanged1,024-operation/performance gates remain separate. Existing native70, decimal12 and optional security compiler interfaces retain their prior scope.
