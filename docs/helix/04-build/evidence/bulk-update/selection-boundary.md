# Trusted portable selection backend boundary

This component implements CONTRACT-006's trusted `SelectionBackend` describe/assess/lower surface in the original Rust core. `MutationRegistry.install_selection_backend` installs executable host code and returns an explicit local handle; selection metadata cannot install code and no frontend backend-ID switch appears. Descriptions are captured once and returned as isolated copies. Exactly interpretation/completeRead claims are accepted; unsupported/unknown declarations or mapping assessments refuse without fallback. Declarations/evidence strings never attest native execution or authorization.

Common dispatch matches exact original model bytes and the selected Key to an installed original UMF preparation target. Original owner preparation supplies selected Record/member/Key semantic closure; unrelated retained Records cannot inherit its admission. Selection transport checks typed AST and original Field literal domains. Key descriptors preserve original UMF decimal/binary meaning instead of inheriting the predicate-only scalar subset. Callbacks and their error diagnostics share bounded validation; supported assessment cannot discard nonempty diagnostics.

Lowered output requires complete identity/version/ordered Key descriptors, native integer identity ordering, maxItems+1, nonempty preflight and obligations. Structural checks do not prove that preflight covers every authorized row: the real backend/native evidence must establish that. SQL is bounded by UTF-8 bytes, scalar literals by original JSON bytes and complete lowering by a16MiB counting writer. This writer uses the pure Rust Write interface for byte counting and performs no filesystem/network I/O. All documented overflows retain WFT-MUTATION-LIMIT separately from malformed ACTION refusals.
