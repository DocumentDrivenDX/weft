# Conditional current-query refinement and explicit Truss query ABI

CONTRACT-010's pure checker is implemented behind the named Cargo feature and
five actual-CQP backend/Python methods. The proposed standard 0.4.35 distribution
explicitly enables that feature. Calling a named checker compares supplied
complete cells/results conditionally; it grants no native permission or protected
consumer admission. Original source/caller/current authority, factual completeness,
retention and guarded release remain native-host duties. All 132 original B-008
shared/native requirements remain required, and prior case acceptances remain
accepted. This increment promotes zero native cases.

## Release validator and limits

Review found that the first release validator could accept reports claiming 30
controls with empty checks. That source and review input remain historical. The
replacement requires the exact 30 ordered identities, closed positive/refusal
flags with actual booleans, all five unique wheel/source/version/pin matches and
negative native/security flags. Twenty synthetic validator controls cover the
counterexample, omissions, duplicates, renaming, status changes and report swaps;
they are not five-platform execution. Release CI must run each actual platform
wheel and require its report before publication. Release metadata distinguishes
the closed runtime-hash backend from the new explicit query-ABI backend.

The checker supports only its declared required String/signed-64 input subset,
operations and bounds. Pre-limit expected cell/order slots and repeated logical
UTF-8 public/key payload are bounded, including LIMIT 0; those are semantic size
limits, not serialized-JSON size, heap, timing or allocation-tracing proofs. A
consistent forged input/count/result world can conditionally match and still
has no native completeness or authority. Original native B-008 gates remain
required. Local wheel hashes are not final public release pins.
