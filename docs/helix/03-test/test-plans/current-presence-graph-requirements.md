# Original graph requirements verification

This is planned coverage for the proposed CONTRACT017 interface. No listed case
is an observed implementation/native pass. All original132 B-008/shared158
requirements and STP009 acceptance rows remain required and unchanged.

## Oracle and custody

Use complete independently authored expected references/Key order, actual
original compiler factories, original UMF semantic validation and genuinely
captured native source/occurrences at their respective layers. Expected results
must not be generated from the helper being tested. Schema admission is only
shape evidence: an unknown target Key name may pass schema while failing
original semantic resolution. Stored receipts or synthetic edge tables cannot
replace current native acceptance.

Every run retains exact source/toolchain/feature/case inputs and ending hashes,
raw failure/refusal outputs, original iteration attempts and cleanup evidence
where native resources exist. No fixture/compiler report is a native witness.
Qualified component checks must not promote a whole shared/backend criterion.

## Required later native and end-to-end families

Use the same actual compiler preparation and accepted model/source pins inside
the original host's held operation. Join issued logical requirements to actual
accepted native type/property/Key/relationship/endpoint definitions. Independently
verify original codec/domain and occurrence/version correspondence, full selected
populations including empty and parallel-edge cases, and original owner/caller/
current-generation custody. Do not use provider substitution or metadata equality
as native admission.

Exercise JSON property homes and actual non-JSON native columns/homes according
to their qualified realization. A catalog row-home tag without realized state/
node/payload storage must refuse; no empty or JSON fallback. Keep relationship
type and edge property-owner type distinct under actual native association
checks. Ordinary/authenticated caller, DDL/source/role/grant/configuration drift,
revocation, held/closed operation, cancellation and cleanup controls remain
required before public release. Scope-specific exclusions must be evidenced,
never inferred from a data report.

Original guard/producer/lowering/result/whole-disclosure/closing-release
composition and every applicable Truss/PostgreSQL and Ashlar/Databricks criterion
remain mandatory. Databricks tests require approved dedicated resources and
separate authenticated callers, an owned client_dev test schema and cleanup.
No local SQL substitute or shared excluded warehouse qualifies that backend.

## Build handoff

Freeze the exact entry wire shape and refusal/capacity semantics before code.
Review the interface against original UMF schema/semantics and existing compiler
identity APIs. Implement in an isolated candidate; retain independent Core tests,
compile-fail/feature clients and effective mutants. Runtime/Python exposure,
backend mapping and actual native guarded execution each require separate
qualification. Full acceptance cannot be inferred from any one layer's pass.
