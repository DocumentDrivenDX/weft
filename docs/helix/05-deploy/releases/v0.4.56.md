# Weft 0.4.56

## Release scope

This is a draft record for the proposed `umf-weft==0.4.56` release. The Python
import remains `weft`; the release is based on the reviewed 0.4.56 producer
source. No release tag, immutable GitHub release, public PyPI upload, or
consumer installation is claimed by this document.

The scoped compiler change selects a Weft module envelope at version 0.2 for
matching non-null literal defaults. Ordinary UMF AST declarations remain at
0.1; omission is not filled into user input, and native-only temporal behavior
is unchanged. This statement records implementation scope, not a completed
release qualification or a broader adapter claim.

## Qualification status

The proposed release uses a local, no-Actions release profile. Its exact scope
is the three `cp39-abi3` wheels for Linux x86_64, Linux ARM64, and macOS ARM64,
plus the bounded source, build, qualification, and asset records described in
the [local operator runbook](../local-release-runbook-0.4.56.md). Local
provenance is unsigned and does not claim a hosted workflow identity.

The bounded Linux source/package guards have an accepted actual result on the
P56 producer, under Linux x86_64, Python 3.11.17 and Bun 1.4.3. That narrower
result does not establish Python 3.12 coverage. The exact x86_64 Linux native
campaign retained 19 raw scenario dispatches and an original `FAIL_OR_UNKNOWN`
operator receipt; a separate reviewer-accepted pure predicate reanalysis found
all 14 case predicates satisfied while preserving that original failure. This
is analysis of the retained run, not a rerun or a new runtime observation.

The x86_64 and ARM64 Linux wheels have accepted static artifact evidence. The
macOS ARM64 wheel has an accepted build/static-audit chain only: the original
build failure and separate static-only audit remain distinct records. None of
these static results establishes macOS installation or runtime behavior. The
reviewed Table012 inherited-boundary receipt and reviewed full Truss011 receipt
are retained under their original profiles; the same Truss011 run supports
both browser and WASM obligations, with exactly ten selected-software witnesses
rehash-verified outside the evidence ZIP. The release remains held pending the normal
metadata merge, M-source review, final assembly review and separately
authorized public transaction. No macOS compiler, native, browser, or
installed-wheel execution is claimed.

The release also requires a normal metadata merge that preserves producer
source identity, a fresh assembly review, and the separately authorized public
transaction. PyPI upload and fresh public-index proof remain unqualified until
the supported owner credential and exact public readback are available.

## Audience and required action

Python consumers should continue using the currently published version until
the release status is changed from draft after all gates and public readbacks
are complete. Do not install wheels from a held local assembly or infer
platform support from a static wheel inspection.
