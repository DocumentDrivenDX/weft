# Weft 0.4.55

## Release scope

This candidate changes the Python distribution name from `weft-sql` to
`umf-weft`. The Python import remains `weft`; compiler protocols, backend
registrations and SQL behavior retain the qualified 0.4.54 compiler base,
including G02 and the integrated Unity/raw-read fixes. Version and distribution
metadata change, so every released wheel requires fresh qualification.

Publication remains pending until the hosted producers, immutable GitHub release,
PyPI OIDC upload and public byte checks pass. The generated `release-pins.json`
will bind the exact source, workflow runs, wheel bytes and native-module bytes.
No note embeds its own commit hash.

## Audience and channels

Python consumers and dependency maintainers receive the change through the
GitHub release and PyPI project. Hosts retain responsibility for execution,
transactions, authorization and their own installed-package admission gates.

## Changes and fixes

The release uses Actions for all three wheel targets: Linux x86_64, Linux ARM64
and macOS ARM64. The macOS producer checks the installed wheel and compares nine
frozen refusal responses across Rust, installed Python and real Chromium WASM.
Linux producers check exact installed packaging only. No sdist is produced.
The existing gated PyPI workflow publishes the qualified bytes using OIDC.

## Breaking changes and required actions

New dependency declarations must use `umf-weft==0.4.55` after publication. Keep
`import weft` and existing protocol identifiers unchanged. Replace the old
distribution in a fresh environment; do not install both distributions together,
because they provide the same import package. Existing immutable `weft-sql`
releases and consumers pinned to them retain their original names and evidence.

## Migration or rollback guidance

Consumers remain pinned until the new public archive hashes match the qualified
GitHub assets and their owning integration gates pass. To hold an upgrade,
retain the previously qualified environment and dependency pin. Recreate that
environment to roll back; do not overwrite a released wheel or relabel an old
receipt as evidence for this distribution.

## Known issues and support

The nine macOS vectors establish refusal-response parity only. They do not
qualify positive query compilation or native PostgreSQL execution. Linux checks
establish packaging identity only. Separate compiler/native evidence retains its
original versions, source and scope; this release adds no production executor,
managed database, generated-client or security authority claim. Consumer
admission and a public fresh-install check are separate gates.
