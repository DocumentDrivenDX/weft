# Weft 0.4.57

## Release scope

`umf-weft==0.4.57` is published on GitHub and PyPI. The Python import remains
`weft`. The three-platform compiler/package qualification and one fresh public
Linux consumer are accepted within the evidence scope below. Native database
permissions and security qualification retain their independent gates.

The temporal compiler profile adds guarded source lowering and four whole-program
read/page shape/current checkers. Temporal programs explicitly select ABI1.3;
ordinary programs retain ABI1.2.

Source rows are validated before filtering.
Temporal continuations retain string keys and full ordering tuples. Strict
CONTRACT-075 syntax, byte/node/output limits, source identities, original
compiler custody and refusal checks remain mandatory.

## Qualification scope and required actions

The selected distribution profile requires three `cp39-abi3` wheels:
Linux x86_64, Linux ARM64 and macOS ARM64. It also includes a source distribution
and an exact repository source archive.

Each wheel requires the closed ordered42
current SDK controls and fresh installed/archive correspondence. Actual raw
temporal WASM requires Node and Chromium parity. Source/tree, canonical UMF
pins, frozen lock, features, resources and GitHub original-job artifact identities
bind production payloads to product source R. The original current42 `/1` profile
continues to require source/controller equality; its validator is unchanged.

The release-specific `weft-current-three-wheel-sdk-controller-pairs/1` profile
may instead use only the explicitly registered Mac R/Q and Linux ARM64 R/A pairs
for product R `c623b94b66b0b46d492d457c62faddc896e2e452`, tree
`cc552d691c92c7abdd44fdf4e4ca585936ae68c5`. Each controller retains its real
GitHub head/tree/workflow/attempt. Complete independently validated Git inventories
must prove production inputs unchanged. This is not a general different-controller
fallback and never fabricates `/1` receipts.

The tag, archives and wheels remain
R; exact controller registration is separate reviewed metadata.

The Mac-only cold build has a90-minute/5,400-second global bound and1,800-second
wheel stage with original30-second termination grace and evidence reserve.
The separately enrolled ARM-only cold acquisition/build has a4,200-second stage
starting before action/image setup, within its own90-minute/5,400-second global
bound and60-second upload reserve. Other acceptance checks remain mandatory,
including closed SDK42 and all nine Mac refusal-parity results. No cache resume
or completion guarantee is claimed.

See the
[controller-pair qualification addendum](../../04-build/plans/current-0457-macos-controller-pair.md)
for exact registration, byte custody, budgets and dispatch/publication gates.
Successful original jobs and R source/WASM proofs are not replayed or relabelled.

Applications selecting the explicit temporal profile must preserve original
request/source/program custody. Compiler matches do not grant native database
permissions, snapshot isolation, guarded publication or security authority.
Native/HF62/security and affected consumer admission remain independent gates.
No historical support evidence is relabelled as current qualification.

## Migration or rollback guidance

Hold publication on any source, lock, resource, artifact or qualification mismatch.
Retain the previously admitted distribution until the replacement cohort and its
consumer captures pass their independent gates. Release dates and actual digests
come from the immutable release and public-index records.

## Audience and channels

Python embedders can install `umf-weft==0.4.57` from the public PyPI index.
Browser embedders use the qualified WASM assets from the GitHub release.

## Highlights

The release adds guarded temporal lowering and four whole-program checkers.
Three-platform Python wheels and Node/Chromium WASM share the compiler core.

## Breaking changes and required actions

Ordinary callers retain ABI1.2; temporal callers explicitly select ABI1.3 and
retain complete original request/source/program custody. No automatic request
or model migration is performed.

Operators must retain host/backend admission and refusal checks. Exact profile
compatibility and native execution qualification remain host obligations.
For a rollout mismatch, hold activation and retain the previously admitted
package rather than rewriting release payloads or relaxing admission.
The release page, PyPI project and this evidence record are the distribution
and support references for this scoped compiler release.

the original proof manifest's58 entries are verified.

projector J identity. The original artifact is never promoted to accepted.

the complete upload parent and checks containment against the actual workflow.

its pure controls do not claim a fresh consumer replay.

Compiler, browser, installed package and public distribution evidence does not
establish native database isolation, full-source native validation, HF62,
SecuritySnapshot or Truss119 acceptance. Those campaigns retain their own
profile-specific qualification and owners.
