# CONTRACT-016: Model requirements runtime and Python bridge

**Type:** library / candidate embedding protocol. **Version:** 0.1-candidate.

## Purpose

Expose CONTRACT-015 original model requirements through CONTRACT-014's existing
issued current-presence runtime/Python objects. Preserve actual original parent
custody across the boundary. Returned JSON remains incomplete correspondence
data; it grants no native authority. All original132 B-008 cases remain required.

## Scope and Boundaries

The separate runtime and Python feature is
`current-presence-model-requirements-candidate`. It MUST enable that layer's
`current-presence-candidate` and the corresponding lower-layer requirements
feature. Default and earlier feature selections MUST NOT expose the new method.
No new Python class, constructor, report importer or WASM export is introduced.
Existing published wheel selection and installed consumer asset pins are separate;
no existing native consumer is activated or silently repinned by this contract.

UMF continues to own semantic admission, policy and original key/domain meaning.
Weft owns original compiler resolution. Native owners join these issued
requirements to actual accepted/native source evidence; they MUST NOT replace
that resolution with a recursive Python UMF, key or policy interpreter.

## Normative Surface

The existing runtime `CurrentPresencePreparation` MAY expose
`model_requirements_json()` only under the new feature. It MUST derive the
scoped Core context from that object's same retained immutable original Arc,
require correspondence to its stored issued context report, invoke the actual
Core requirements factory and return its exact JSON bytes. It MUST NOT parse
caller-supplied preparation/SQL/report JSON, invoke a public callback, retain an
equal replacement parent or import a requirements capability from JSON.

The existing frozen Python `weft.CurrentPresencePreparation` MAY expose
`model_requirements_json()` only under the new feature. It takes no caller
arguments, MUST first verify the existing actual Python-parent/runtime-original
custody, invoke the matching runtime method and return its string unchanged.
`source_preparation()` MUST continue to return the same Python object; deleting
the caller's parent variable MUST NOT invalidate the retained original. A
separately issued byte-identical preparation MUST remain a different parent.

The return value is exactly the CONTRACT-015 data report, including full original
request strings, descriptor identities, original model/source/preparation pins,
ordered Keys, false completion/authority/securityReady and all unresolved native
obligations. The existing16,000,000-byte Core output bound remains unchanged.
No new coercion or caller-controlled input string surface is introduced.
Native owner decoder, accepted-source and physical-binding capacities remain
separate composed limits. This bridge MUST NOT raise those guards or claim a
whole-host capacity solely from its Core output bound.

## Precedence and Compatibility

CONTRACT-014 retains authority over class construction, frozen instance shape,
actual-parent checks, old uniform class isolation and feature absence.
CONTRACT-015 retains authority over report content and independent persistent
binding/context construction order. A returned requirements string MUST NOT be
fed back into its original persistent binding or treated as an issued context.

This pure bridge has no native transaction, caller, deadline or current-authority
handle. It therefore cannot declare a native operation live, closed, admitted or
releasable. The actual native owner MUST retain the same issued preparation and
reject wrong, closed or stale operation custody when joining/executing these
data; successful JSON production after a host operation ends grants no authority.
No closed-operation refusal is claimed from the pure Python method itself.

## Error Semantics

Python wrong receiver types, imported dictionaries/strings, old scalar contexts,
constructor/copy/pickle/subclass attempts and additional arguments MUST refuse
through the existing native type/signature boundary. No user coercion callback
may be called. Failed actual-parent custody MUST retain
`WFT-CURRENT-PRESENCE-BRIDGE: Current presence bridge refused`.
Existing original compiler requirements failures retain their diagnostic code and
message, mapped to Python ValueError. Failure MUST return no partial JSON,
construct no substitute context, issue no native token and schedule no retry.

## Examples

`child = original.prepare_current_presence()` followed by
`raw = child.model_requirements_json()` returns data from that same original.
`child.source_preparation() is original` MUST hold. After deleting the local
`original` variable, the child retains its actual parent and still returns the
same requirements data. Calling the new method descriptor on an old
`CurrentQueryPreparation`, a parsed report dictionary or a report string MUST
refuse. Old presence-only and default wheels MUST lack this method.

## Validation and Unresolved Evidence

Compare actual runtime output byte-for-byte to the actual Core requirements
factory on original supplied data fixtures, including nested descriptor
identities and optional availability. Exercise actual Python native types from
new opt-in, older presence-only and default builds: method presence/absence,
same-parent retention after garbage collection, wrong receivers/additional
arguments/no-coercion, no importer/reconstruction, exact original request/pins
and complete independently authored Field/Key mappings. Existing whole-disclosure
bridge tests remain required for the combined candidate feature selection.
Native accepted-source/physical/codec joins, relationship mapping, actual
operation/caller/current authority, closing guards and guarded release remain
unproved by these embedding tests. No acceptance case is promoted.
